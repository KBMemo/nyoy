= kbmemo エコシステム — Nyoy MCP を前提とした構成

如意（Nyoy）の MCP サーバー公開（Phase 6）を受け、3 アプリ（徒然・葛籠・如意）と外部クライアント（Cursor 等）の
**責務分界と連携経路**を再定義する。

* 徒然リポジトリ: link:https://gitea.artif.org/Artif.org/kbmemo_site[kbmemo_site]（`~/work/kbmemo/site`）
* 如意リポジトリ: 本リポジトリ（`~/work/localai/nyoy`）
* MCP 運用詳細: link:../mcp-server.md[docs/mcp-server.md]
* 徒然 Chat エージェント: `site/docs/architecture/chat-agent-roadmap.adoc`

== 1. 前提（2026-07 時点）

如意は次を **実装済み** とする。

* **Chat UI** — `ChatTools::Registry` によるツール付きチャット（`ruby_llm`）
* **MCP サーバー** — 同一 `ChatTools::*` を HTTP（`/mcp`）と stdio（`bin/mcp-stdio`）で再公開
* **SD パイプライン** — MCP 拡張ツール（`generate_image` / `refine_image` / `list_prompt_styles`）
* **接続管理** — `ServiceConnection` + `NyoyConnectionStore`（llama / SearXNG / 徒然 API / 葛籠 / sd.cpp 等）

徒然は **in-app Chat::Agent**（intent ルーティング・pgroonga/pgvector RAG）を Phase 0–2 / 5a–5b まで実装済み。
Web / URL / Vision / 画像生成ツールは **徒然内未実装**（Router は名前のみ返す）。

== 2. 設計原則（更新）

[cols="1,3"]
|===
|原則 |内容

|正本の分離
|メモは徒然、バイナリは葛籠。如意は AI 処理とオーケストレーションに専念する（従来どおり）。

|ツールの単一実装
|**重い・横断的なツールは如意 `ChatTools::*` に1か所だけ実装**する。Chat UI と MCP は `Mcp::ToolBridge` で共有（従来どおり）。

|徒然はメモ体験と in-process RAG
|徒然 DB 上の pgroonga + pgvector RAG は **アカウントスコープ・低遅延**のため徒然 `Chat::Agent` に残す。Nyoy の `recall_memos`（export 取込 RAG）とはデータ経路が異なる。

|外部エージェントは Nyoy MCP
|Cursor 等は **徒然にツールを複製せず**、Nyoy MCP（本番 `https://nyoy.kbmemo.net/mcp`）へ接続する。

|API 契約で疎結合
|徒然 ↔ 如意は OpenAPI（`docs/openapi/kbmemo-v1.yaml`）と MCP。徒然の検索エンジン差し替えは HTTP 形状を維持すれば如意側は不変。
|===

[cols="1,2,2"]
|===

== 5. クライアント別の推奨構成

=== 5.1 Cursor（徒然 Workspace）

徒然リポジトリの `.cursor/mcp.json` で Nyoy MCP（HTTP 本番）に接続する。
雛形: 徒然 `docs/architecture/nyoy-mcp.adoc`、如意 `docs/examples/cursor-mcp-http.json`。

* メモ検索・保存 → `search_memos` / `get_memo` / `create_memo`
* Web 調査 → `web_search` / `fetch_url`
* 画像生成 → `generate_image` → `refine_image`
* **徒然コード内に同等ツールを増やさない**

=== 5.2 徒然 in-app Agent（`/agent_chat`）

現行パイプラインを維持しつつ、未実装ツールフェーズの方針を変更する。

[source,text]
----
User → IntentClassifier → Router → [実装済みツールのみ] → LLM → Escalation
----

* **実装済み（徒然内）**: `rag_search` / `memo_search`（pgroonga 系）
* **Nyoy MCP に委譲（徒然では実装しない）**: `fetch_url`, `web_search`, `image_analysis`, `image_generation`
* **UI で案内**: Router が未実装ツールを返したとき、pending 表示に加え「如意 MCP / 如意 Chat UI を利用」と示す（任意）

将来オプション: `Chat::NyoyMcpClient` で MCP `tools/call` を in-app から呼ぶ（HTTP 往復・認証が増えるため **後追い**）。

=== 5.3 如意 Chat UI

従来どおり `ChatTools::Registry` + ローカル LLM。MCP とは別入口だが **ツール実装は同一**。

=== 5.4 メモ編集 AI パネル（執筆特化）

intent ルーティングは通さない（`MemoAiChat`）。執筆支援に特化。変更なし。

== 6. 徒然 chat-agent-roadmap のフェーズ見直し

`site/docs/architecture/chat-agent-roadmap.adoc` の Phase 3–7 を次のように **再定義**する。

[cols="1,1,3"]
|===
|旧 Phase |新方針 |内容

|3 URL 要約
|**委譲**
|徒然に `Chat::Tools::FetchUrl` を実装しない。Nyoy MCP `fetch_url` / `search_fetched_page` を使用。

|4 Web 検索
|**委譲**
|徒然に `Chat::Tools::WebSearch` を実装しない。Nyoy MCP `web_search` を使用。

|5a/5b RAG
|**徒然で継続**
|in-app Agent 用。変更なし。

|6 Vision
|**委譲**
|Nyoy MCP `analyze_image` または `run_image_understanding_graph`（`tsuzura_media_id` または如意 Chat 添付経路）。

|7 画像生成
|**委譲**
|Nyoy MCP `list_image_generation_options` → `generate_image`。ラフ案は `refine_image` で仕上げ、direct は `generation_flow=direct` で直接 txt2img。

|8 会話永続化
|**徒然で継続**
|in-app Agent の履歴 DB 化。Nyoy Chat の `chats`/`messages` とは別系統。
|===
